DFIP Case Management + Tkinter Application (updated)

HOW TO RUN (Windows)
1. Extract this ZIP to a folder (do not run inside the ZIP).
2. Double-click START_DFIP.bat or run: py main.py
3. Sign up or log in, then open the Cases tab.
4. Click Add Case, fill title, client, description and priority (1-3).
   The Case ID is generated by SQLite when you save.
5. View All loads saved cases. Search takes a Case ID.
   Sort by Priority displays cases in descending order (3, 2, 1).

APPLICATION LOGIC
- main.py starts Tkinter, handles login/sign-up and opens the dashboard.
- dashboard.py displays pages, case entry and results. It calls the backend.
- cases.py validates case inputs and asks database.py to save the case.
- validation.py checks required fields and priority values.
- database.py creates tables, handles authentication/reports, and saves cases
  with SQLite-generated IDs. Data persists between application launches.
- search.py performs linear search on the saved cases.
- sorting.py performs Bubble Sort on a copy of the saved case list.
  Sorting changes only the display order, not the database.
- theme.py provides the UI styling. Reports are now linked to registered cases.

DESIGN NOTES
- New cases start with status Open. Case status editing is not implemented.
- Case IDs may have gaps if older cases were removed. Do not assume consecutive IDs.
- Priority 3 is highest; 1 is lowest.
- All signed-in users currently see and can add cases; case-level permissions
  are not implemented. Do not use for confidential live investigations.
- New reports require an existing Case ID, selected from a dropdown.
- Reports display their related Case ID and support searching by it.
- Existing reports are preserved as Legacy (not yet linked to a case).
- Report assignment and outcome editing continue to follow existing roles.
- The ZIP does not include existing accounts or database data.
- Keep dfip_users.db and any credentials out of GitHub.
- Optional: pip install keyring for Remember Me support.

REPORTS WORKFLOW
1. Log in and create a case in the Cases tab.
2. Open Reports, click New report, and choose the case from the dropdown.
3. Enter the report title and description and submit.
4. The report list and details show its related Case ID.
5. An admin can assign reports to experts; experts can record outcomes.
6. Existing reports from older versions are preserved as Legacy.

UPGRADING AN EXISTING INSTALLATION
Back up dfip_users.db before upgrading. Extract this ZIP into a new folder.
Copy your backed-up dfip_users.db into the folder beside main.py, then launch.
The application adds the reports.case_id column automatically without
deleting previous reports. Do not include the database in a GitHub commit.

CASE REPORTS AND STATUS (NEW)
- Select a case in Cases and click Case Reports to show only its linked reports.
- Report visibility still follows existing roles (user: own, expert: assigned, admin: all).
- Click the Reports navigation tab to clear the case filter.
- Admins and experts can change case status: Open -> In Progress -> Closed.
- To close a case, at least one linked report must have an outcome and all
  linked reports must be completed. A closed case can be reopened to In Progress.
- Report completion does not automatically close the case.
- This is an educational prototype, not a production investigation system.
